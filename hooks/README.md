# Harness gates

Deterministic quality gates shipped with the afk plugin. Stop gates and the `lavish-dark.sh` PreToolUse hook are wired in `hooks/hooks.json`; `app-start-gate.sh` is on-demand. All gates run against the repo the session works in (`git rev-parse --show-toplevel`); the Maven/format gates no-op outside a core-services-shaped checkout (no `all-modules-pom.xml` at root ⇒ silent allow).

| Gate | Trigger | Blocks when | Typical cost |
|---|---|---|---|
| `wiring-gate.sh` | Stop hook, any NEW file (worktree + unpushed commits) | new artifact has zero referrers and no IOU in `.claude/wiring-ious.md`; with `WIRING_FINAL=1`, open IOUs also block | ~1–5s |
| `skill-registry-gate.sh` | Stop hook, this plugin's checkout present | a `skills/afk/*/SKILL.md`, `skills/utils/*/SKILL.md`, or `agents/*.md` isn't listed in `.claude-plugin/plugin.json`'s `skills`/`agents` array (invisible to the plugin loader), or an array entry points at a dir that no longer exists | <1s |
| `maven-compile-gate.sh` | Stop hook, changed `.java` | any changed submodule fails `compile` (reactor, `--also-make`) | 30s–3min |
| `ui-lint-gate.sh` | Stop hook, changed `.js/.ts/.vue` | ESLint errors in changed files (nearest `.eslintrc.*` workspace) | ~10s |
| `java-format-gate.sh` | Stop hook, changed `.java` | changed file not conformant to the repo-root `eclipse-code-formatter.xml` (STRICT: touched legacy file ⇒ reformat whole file via the Fix command it prints) | ~5s/module |
| `lavish-dark.sh` | PreToolUse hook on Bash/PowerShell, command is a `lavish-axi <file>` render | never blocks — forces dark mode on the artifact HTML before render (lavish-axi has no theme param): DaisyUI artifact ⇒ `data-theme="dark"` on `<html>`; otherwise ⇒ luminance-gated invert override; idempotent via marker comment; non-render subcommands and non-HTML args no-op | <1s (non-lavish commands: ~0s) |
| `app-start-gate.sh` | on demand (NOT a Stop hook) | service fails to boot: `package --also-make` + `java -jar`, watches for `Started *Application` | 3–6min (`APP_START_REUSE=1` hit: ~0s) |
| `mutation-probe.sh` | on demand (NOT a Stop hook) | never blocks — prints PIT mutation results (`ok` with survived/no-coverage mutants, or `unavailable`) for the review gate's test-strength signal | 2–15min |

Rules:

- Escape hatch for all Stop gates: create `.claude/hooks/.gate-disabled` **in the repo being gated** (leave a reason inside; delete to re-enable).
- **Pass cache.** The three code Stop gates (compile / lint / format) remember their last **pass** as a content hash (`gate-cache.sh`, sourced by each; key = HEAD + every working-tree change's path + blob hash) under `.claude/hooks/.gate-cache/` in the gated repo. A Stop firing on an unchanged tree skips the gate's work entirely — a cache hit emits no metrics line (no-op, like a scope no-op). Failures store nothing. `GATE_CACHE_DISABLE=1` forces every run to do real work.
- Wiring gate is mechanical zero-referrer detection only (token = filename sans extension, `git grep --untracked`). Framework-wired classes (`@RestController` etc.) and convention-consumed files (README, SKILL.md, tests, migrations, specs) are skipped. Weak-consumer judgment (test-only consumers, unreachable flows) is `/verify-seams`' job. Ledger format lives in the repo's `.claude/wiring-ious.md` — IOUs anchor to a plan step/ticket/contract, never a guessed future filename; auto-closed when a referrer appears.
- Maven-invoking gates serialize via `maven-lock.sh` (lock dir `.claude/hooks/.maven.lock` in the gated repo, mkdir-based, stale-stolen after 30 min) — two concurrent reactors race on shared `target/` dirs and fail with bogus "cannot find symbol". Wrap any new gate's mvnw call in `acquire_maven_lock`/`release_maven_lock` (source via `$(dirname "${BASH_SOURCE[0]}")/maven-lock.sh`).
- Maven invocations are reactor-based with `--also-make` — never trust `~/.m2` for sibling modules; stale jars cause APT `Expected a DeclaredType, got <error>` false failures.
- `mutation-probe.sh <module> <targetClasses-csv> [targetTests-csv]` runs PIT scoped to a slice's changed classes and prints which mutants the tests failed to kill — the empirical test-strength oracle behind the review gate's test-veracity sampling (that skill owns the sampling rule). Exit 0 = signal printed; exit 3 = `unavailable`/timeout (infra or the missing per-service `pitest-junit5-plugin` pluginManagement entry — snippet in the script header), which callers treat as "no signal", never a failure. `PITEST_VERSION` / `MUTATION_TIMEOUT` env-tunable.
- `app-start-gate.sh [leaf-module]` (default `11700-payable/payable`), run from the repo root: `bash tools/payable/ai-agents/plugins/workflow/hooks/app-start-gate.sh`. Exit codes: 0 started, 2 code failure, 3 environment failure (infra down / port busy — not a code bug), 4 timeout. Env vars: `APP_START_TIMEOUT` (default 300s), `APP_START_PORT` (default 0 = ephemeral probe), `APP_START_KEEP=1` (provisioning mode — leave the instance running, prints pid + stop command), `APP_START_SKIP_UI=false` (package the UI into the jar so the instance serves the rebuilt frontend), `APP_START_REUSE=1` (reuse a still-alive kept instance on the fixed port as-is — no rebuild, no reboot; falls through to a full boot if none). A kept fixed-port instance is recorded in `.claude/hooks/.app-instance-<port>` (pid/winpid/module/jar) in the gated repo; the next fixed-port run kills that recorded instance itself before booting, so re-provisioning never hits a port-in-use false env failure.
- Java format fix: the gate prints the exact `formatter-maven-plugin:format` command scoped to the failing files. Formatter config is the repo-root `eclipse-code-formatter.xml`.
- **Latency metrics & budget.** Every gate run doing real work (scope-check no-ops excluded) appends one JSONL line to `.claude/metrics/gate-latency.jsonl` **in the gated repo** via `gate-metrics.sh` (sourced by all seven gates): `ts`, `gate`, `result` (`pass`/`blocked`, or `ok`/`code_failure`/`env_failure`/`timeout` for app-start), `duration_ms`, plus gate-specific fields (`lock_wait_ms` = maven-lock serialization tax, `package_ms`, `detail`). Summarize with `bash tools/payable/ai-agents/plugins/workflow/hooks/gate-metrics-report.sh` (per gate: runs, red count, p50/p95/max).
- `skill-registry-gate.sh` checks are mechanical (dir/entry existence + array membership) — never validates SKILL.md content. Add a new `skills/afk/<name>` or `skills/utils/<name>` dir → add its `./skills/.../<name>` string to `plugin.json`'s `skills` array in the same commit, or this gate blocks the next Stop. Budget: p95 should stay within the **Typical cost** column above — a sustained breach triggers optimization (compile gate: check `lock_wait_ms` share first, then evaluate `mvnd`/offline `-o`; app-start: check `package_ms` vs boot time, `APP_START_SKIP_UI`), never optimize a gate without this data. `GATE_METRICS_DISABLE=1` silences emission; emission failures never fail a gate.
- UI lint config: each changed file is gated by the **nearest ancestor `.eslintrc.*`** (that directory becomes the lint workspace, e.g. `11700-payable/payable-ui/.eslintrc.js`); the `eslint` binary resolves from the hoisted root `node_modules` via `npx --no-install`. No config or no eslint ⇒ silent allow.
