## Goal
Build the job supervisor scripts/team/supervisor.py (file name: plan decision D-3): one watcher process per agent, started by agent-start through the watched-agent-id field, that sends the contact agent exited when the watched agent ends, and parked with the provider's reset time in a body file where it owns the output stream (the headless kind, TR-2). The slice ends at the supervisor: starting it, refusing a second one and writing its process entry belong to the team entry script and the contact agent.

## Acceptance
- [ ] Implements the public interface in SDD §8 row "Job supervisor" unmodified: agent-send exited or parked, only to the contact agent, as the watched agent (its agent-id, role and owner generation) (SDD §8 row "Job supervisor")
- [ ] The supervisor's message id is the watched agent-id, then 'sup', then the supervisor's own counter, so it never matches an id the agent makes (SDD §8 row "Job supervisor")
- [ ] It sends only parked and exited, and only to the contact agent (SDD §3)
- [ ] parked carries the reset time in a body file whose free text holds the time in UTC ISO 8601, as in 2026-09-29T10:15:00Z; the body path is empty only for exited or an unknown reset time (SDD §3)
- [ ] The supervisor sends parked with the reset time only where it owns the agent's output stream, the headless kind (TR-2) (SDD §8 row "Job supervisor")
- [ ] A parked message carrying the provider's reset time lets the contact agent park the role beyond the provider's wait horizon with a dated report, rather than run a reduced shape (PRD AC-023)
- [ ] The supervisor substitutes no model and decides nothing: its parked message carries the reset time it saw, so the contact agent can continue a single-model role on an equivalent model from another provider or have a debate role wait (PRD AC-022)
- [ ] An exited message from the supervisor is one of the signals that an agent died mid-work, after which the contact agent stops the old agent and resumes it, or starts a replacement that reads the checkpoint (SDD §7)
- [ ] The supervisor's process entry is labelled with the watched agent's pane label followed by the word supervisor, which is what the cleanup report names, agent-decided (SDD §13 Q45)
- [ ] The supervisor is started by agent-start with watched-agent-id as its one field; it writes nothing into the manifest itself, and the contact agent writes its process entry from agent-start's answer, agent-decided (SDD §13 Q42)
- [ ] An agent has 0 or 1 job supervisors; a second supervisor for one agent is refused at start with exit 2, naming the agent (SDD §6)
- [ ] Conforms to ADR-0006 — lifecycle messages reach the contact agent, which keeps the manifest from them; no silent pattern substitution (ADR-0006)
- [ ] Every artifact in ## Produces exists with its declared contract (SDD §8 row "Job supervisor")
