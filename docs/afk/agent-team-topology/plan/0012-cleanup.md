## Goal
Build cleanup scripts/team/cleanup.py (file name: plan decision D-3): one call per run that runs five fixed steps (kill every process the manifest names through agent-stop, then delete the message area, the knowledge store, the resolved pattern and, last, the manifest), keeps every file while any entry stays unkillable, and reports by name every survivor, every pane still open and every stray it finds but never stops. The slice ends at cleanup: the transport kinds' agent-stop and agent-list, the manifest module and the knowledge store are other subtasks, and calling cleanup at a run's end is the team skill's work.

## Acceptance
- [ ] Implements the public interface in SDD §8 row "Cleanup" unmodified: five fixed steps, one call per run, reporting survivors (SDD §8 row "Cleanup")
- [ ] Step 1 kills every process the manifest names, the inbox wait job and each job supervisor included, by calling agent-stop on every remaining agent entry, a lost entry included; agent-stop kills by the process id when the entry holds one, closes the pane when it holds a handle, and kills only after the identity check, agent-decided (SDD §8 row "Cleanup")
- [ ] Steps 2 to 5 delete the message area of the run directory (message bodies, inboxes with their processed folders, completion signals and result files in the run directory), then the knowledge store, then the resolved pattern, then the manifest, last (SDD §7)
- [ ] A phase does not report finished while the manifest holds an unkilled process; a failed kill leaves the entry unkillable and holds the phase (SDD §6)
- [ ] While any entry stays unkillable, or a process entry is left after a failed kill, cleanup skips steps 2 to 5, and its report says the message area, the knowledge store, the resolved pattern and the manifest are kept for the next cleanup, agent-decided (SDD §7)
- [ ] The charter files in the run directory are deleted with the run directory in step 2, the design's inferred reading (SDD §4)
- [ ] A result file that a stage placed outside the run directory keeps the lifetime of its stage and is not deleted (SDD §7)
- [ ] Cleanup kills every process the manifest names and closes every pane the run opened, and reports by name every process it could not kill and every pane still open (PRD AC-013)
- [ ] Before a kill, cleanup checks that the recorded identifier still names the recorded process; on a mismatch, or when no process has that identifier, it kills nothing, removes the entry and reports it already gone, moving an agent entry to cleaned instead of removing it (PRD AC-013)
- [ ] An entry that holds a process id and no started-at gets no kill: stopped true with the method 'already gone' and a move to cleaned when no live process has that id, else stopped false with the reason 'identity unknown' and a move to unkillable, named in the report by agent name and process id, agent-decided (SDD §8 row "Cleanup")
- [ ] An entry that holds neither a process id nor a handle gets stopped true with the method 'nothing recorded', moves to cleaned and is named in the report by agent-id and agent name, agent-decided (SDD §5)
- [ ] A recycled process id leaves its entry unkillable until that process ends, the report names the agent name and the process id, and the run stays parked; this residual is accepted, agent-decided (SDD §13 Q51)
- [ ] A stop or a pane close that fails marks the entry unkillable, a failed close names the pane, and run cleanup tries again (PRD AC-050)
- [ ] On TR-4, cleanup closes each recorded terminal by its terminal identifier through agent-stop, and reports by name any terminal it could not close (PRD AC-031)
- [ ] A background process started by an agent and never registered is still killed when its owning agent's process tree is closed (PRD AC-014)
- [ ] A process started through Windows Management Instrumentation is outside the job and the descendant sweep, so it is covered only when registered; the cleanup seam test adds this case (SDD §13 Q10)
- [ ] Cleanup stops no agent the manifest does not name: it lists each stray, by agent name and pane id, in its report, and the human stops it, agent-decided (SDD §13 Q38)
- [ ] A stray is told by its pane id: an agent agent-list returns whose pane id no manifest entry holds, and agent-list matches names that start with the legal goal cut to the shortest common prefix of that goal and each non-empty agent name in the run's manifest, agent-decided (SDD §13 Q40)
- [ ] When agent-list answers exit 3, unsupported, cleanup skips the stray list and its report says the kind cannot list agents, agent-decided (SDD §13 Q43)
- [ ] A kind whose handle is not a pane id, TR-4 included, answers agent-list with exit 3, and cleanup handles it the same way, agent-decided (SDD §13 Q48)
- [ ] An interrupted cleanup leaves the manifest listing entries, and the next cleanup finishes it (SDD §7)
- [ ] The knowledge store is deleted at cleanup and nothing in it is promoted first (PRD AC-019)
- [ ] The cleanup report carries each signal the design names: unkilled processes with agent name and process id, the kept-files notice, every pane still open, each stray or the notice that the kind cannot list agents, and each 'nothing recorded' entry (SDD §5)
- [ ] Before this subtask merges, the PRD test starts a process tree under a Windows job with the kill-on-job-close limit and no breakaway limit, with a child a job member starts, closes the owner, and asserts nothing survives (SDD §13 V30)
- [ ] A process outside the agent's job is killed by its registered identifier and by the descendant sweep, and one it cannot kill is reported by name (SDD §9b row "Operating-system job owning a process tree")
- [ ] Cleanup relies on agent-stop's TR-4 terminal close and names a failed close in its report (SDD §9b row "Desktop-tool terminal close verb (TR-4)")
- [ ] Cleanup relies on agent-stop's pane close, which sends no signal a shell trap catches, and names a pane it could not close (SDD §9b row "Capture time limit and pane close")
- [ ] Conforms to requirement ADR-0007 — registering a process is not cleanup; cleanup kills and checks; no silent pattern substitution (requirement ADR-0007)
- [ ] Conforms to requirement ADR-0018 — nothing in the knowledge store survives the run (requirement ADR-0018)
- [ ] Every artifact in ## Produces exists with its declared contract (SDD §8 row "Cleanup")
- [ ] The seam-test asserts on the operating system's real output: after the owner closes, no process of the tree is alive (SDD §9b row "Operating-system job owning a process tree")

> (PRD Testing Decisions) | Cleanup + run manifest | Start a process tree, close the owner, assert nothing survives — the case a live trial proved does not hold by default on Windows. Assert the unkillable process is reported by name, not silently dropped. A recorded identifier that now names another process is not killed; its entry is reported as already gone. A pane whose close fails is named in the report. |
> (requirement ADR-0007) Cleanup must kill a background process an agent started and never recorded. The original requirement assumed closing an agent took its descendants with it, so a manifest of registered processes was a safety net over an operating-system guarantee. A live trial refuted that assumption: a headless parent exited cleanly with status 0, and both a child and a grandchild kept running until killed by hand.
> (requirement ADR-0018) The knowledge store is excluded from version control and deleted with the run, and nothing in it is promoted to another record first. Each run detects its environment again, as detection reads the session it is in, not the machine. This supersedes ADR-0002, whose consequence promoted qualified environment facts into a durable register before deletion.

during implementation, classify per the decision protocol (`DECISIONS.md`,

`plan/DECISIONS.md` and implemented; a one-way door or a tie exits
`design_conflict` quoting the SDD section + the conflict. Never override off
the record. Parked conflicts route back to `/afk:grill-solution` for a
superseding ADR.
