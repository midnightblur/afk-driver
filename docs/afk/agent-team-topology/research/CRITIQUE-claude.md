## c. Ideas from PROPOSAL-codex I adopt over my own

1. **Separate three completions**: result completion, transport exit, cleanup completion. My `close` verb returned one boolean; it now returns `{result, exited, cleaned}` and the roster records each.
2. **Receipts with identity that survives PID reuse**: persist creation time or OS handle with the PID, plus an idempotency key on `spawn`/`send`; reconcile roster against transport state before any spawn after a contact restart.
3. **Consumer receipts before termination**: a producer closes only after the store validator passes *and* each named consumer has recorded accepted / stale / disputed / missing for its inputs. My design verified the producer side only.
4. **Builder permissions**: an owned worktree separates files, not credentials. `yolo-in-worktree` becomes available only under an explicit `team.containment` policy the human sets; default builder permissions stay as today.
5. **`managed` topology semantics**: bind user-created agents by explicit identifiers and permissions; never terminate a user-owned session.
6. **Same-provider debate**: when multi-model is off, two independent same-provider agents run the identical protocol; a task that *requires* cross-provider review blocks explicitly when the second provider is unavailable.
7. **Failure classes in the probe**: quota exhaustion, missing entitlement, login failure, network failure, local sandbox failure are distinct answers, never collapsed into "auth failed".
8. **Catalog of pointers**: a rendered index (subject, ids, scope, file pointer) that copies no claims — I make it the output of `afk-fact render`.
9. **`supersedes` / `extends` links and visible conflicts**: conflicting facts stay visible until adjudicated; timestamps never decide truth.
10. **Phase 1 scope**: the store plus termination receipts around today's native children is a smaller first slice than mine and already delivers goal 3 ("kill a planner; a fresh consumer answers from accepted evidence"). I split my phase 1 accordingly (see d.j).
11. **Measure the store**: reused claims, stale inputs, repeated research, claims lost at termination — retro metrics.

## d. Revised position per BRIEF section

- **(a) Topology**: `team.topology` ∈ unset/`native` (default), `managed`, `team`; `none` dropped; built-in patterns `second-opinion`, `panel` (= my planner-duo, generalised to N reviewers/planners), `delivery` (= my pipeline, contact-managed, autopilot stays sequential); `hierarchy` deferred until a transport proves nesting.
- **(b) Lifecycle**: lifespans turn/phase/feature unchanged; close protocol = compaction brief → `afk-fact add` → validator → consumer receipts → `close` returning result/exit/cleanup states; roster ledger stores PID + creation time + idempotency key; contact reconciles roster vs transport on restart; watchdog exit is the silence trigger.
- **(c) Knowledge store**: `{spec-dir}/knowledge/FACTS.jsonl`, append-only, sole writer `scripts/afk-fact.py`, events added/verified/refuted/expired/superseded/extends, deterministic re-verify by line hash / command exit / expiry condition, rendered `FACTS.md` + catalog index; investigation ids linked, never duplicated; not routed through the notes family.
