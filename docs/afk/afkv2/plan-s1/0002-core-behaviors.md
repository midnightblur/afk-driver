# 0002-core-behaviors

## Goal
Write the core behaviors: one rule text of at most 8,000 characters, grown from
the interim behaviors (the "AFK v2 interim rules" block in the user instruction
files) and v1 `BEHAVIORS.md`, with the one search command of AC-021. Build the
provider variants through the plugin check, prove the full text reaches a live
Claude session, and re-run the search benchmark.

## Acceptance
- [ ] The core-behaviors file has at most 8,000 characters; a copy with 8,001 characters fails the plugin check (PRD §AC-014)
- [ ] The text names one search command for every code search: `rg --hidden -g '!.git' PATTERN PATH`, always with a path, and says why: without a path rg reads stdin and can hang (PRD §AC-021)
- [ ] The text carries the interim rules (worktree, commit often, Draft change, merge not rebase, selective tests, ownership grades, decide two-way doors, verify instead of asking) in Simplified Technical English, with no v1 name (PRD §SK-03)
- [ ] The prebuilt provider files are regenerated by the plugin check and are not stale (ADR-0005 design)
- [ ] In a live Claude session the full text arrives in context, not a file path with a preview: the agent quotes the last rule and the end marker (PRD §AC-014)
- [ ] Benchmark rerun on the benchmark repository (PLAN.md "Inputs"): the core search command returns the same hits as `git grep --untracked` in at most 60% of its time, median of 5 runs, rg run with stdin closed (SDD §10)
