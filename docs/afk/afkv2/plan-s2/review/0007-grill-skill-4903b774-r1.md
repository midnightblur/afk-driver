## r-001 high correctness (logic-correctness)
`afkv2/skills/grill/scripts/grill_log.py:189`

Redefining an existing glossary term deletes the lines under its definition, including the Related/Avoid line.

Why: afkv2/GLOSSARY.md uses '**Term**:', the definition, then a '`Related:` ...' line with no blank line between. The pattern (?:.+\n?)* swallows all of those lines and the replacement writes only term and definition. A term written in the inline form '**Term**: text' does not match, so a duplicate entry is appended.

Fix: Replace only the definition line(s) and keep any line that starts with '`Related:`' or '`Avoid:`'; match the inline form too.

## r-002 high correctness (logic-correctness)
`afkv2/skills/grill/scripts/round_document.py:200`

The check that every returning point has a new card counts any mention of the old card id, so a card that only depends on it counts as carrying it.

Why: Round 1 leaves debate card i-3 open and unanswered. Round 2 adds a decided card with depends_on ["i-3"] (the 'holds if' case in ROUNDS.md:48). _decided_fields writes 'depends-on: i-3' into its body, so _names_card matches and the build passes. i-3 is never asked again. The gate reads only the current round (grill_log.py:209) and returning() skips an open old card with no note, so the exit gate can pass with i-3 unsettled. The same mention test in _carried (round_document.py:183-186) drops a reopen mark on a settled card when any later-round card lists it. That reopen has no note, so the end point is the own round and any later mention counts.

Fix: Count a card as carrying a point only when its body names the id in a dedicated carry field or component, never in depends_on or free text; make _carried compare against the round of the reopen, not the card's own round.

## r-003 high correctness (logic-correctness)
`afkv2/skills/grill/SKILL.md:68`

Step 5 says 'On check, fix the named field', but no command can fix a built round. A second build is refused.

Why: build writes the round to the document and appends it as current with no answer. The engine check (props are checked by the engine, not by the builder) can then refuse it, for example a bad table prop. A second build runs _close_current and refuses with round-not-sent, so the agent must hand-edit the JSON document or stop. Unverified: the real engine is not in this tree, and only the fake engine was available.

Fix: Let build replace the current round when it has no answer, or run the check on the round input before the document is written.
