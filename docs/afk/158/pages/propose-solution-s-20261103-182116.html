R-2 One run at a time: a Windows file lock Decided settled by mark l8-lock

Settled by mark in round 2 (accept)

Decision

gc opens afkv2-gc/<encoded branch>.lock and takes a Windows byte lock on it (msvcrt.locking, no wait). Windows releases the lock when the process ends, crash included. A second run gets 'locked'.

Why this one

The operating system releases it, so no stale lock needs a check of whether its owner still lives.

Other options considered (rejected)

  • A lock file that holds the process id and start time, as v1's records do: it needs a liveness check, and a wrong check blocks gc or lets 2 runs in.
  • No lock: 2 agents in 2 sessions could both delete the same folder and report false failures.

Evidencespec

learn.microsoft.com LockFile, Remarks: 'If a process terminates with a portion of a file locked or closes a file that has outstanding locks, the locks are unlocked by the operating system.' msvcrt.locking calls this lock. afkv2 runs on Windows only (PRD Out of Scope).

To undo

Swap the lock helper in gc_target.py.
