R-4 How gc deletes branches Decided open i-branchdel

Git's normal delete refuses both branches on the normal path. gc's own checks take its place.

Decision

gc deletes a branch with git's force flag, but only after its own checks pass: the forge says merged, and the branch tip is the change's head commit or older. The remote feature branch passes the same tip check. The run branch, which never reaches the forge, goes after the merge proof.

Why this one

The run branch is an orphan, and a squash merge leaves the feature tip outside the target, so git's normal delete refuses both. 'gc never forces' means: gc never goes past a refusal without your yes.

Other options considered (rejected)

  • git's normal delete only: it refuses every squash merge and every run branch
  • force with no tip check: commits made after the merge are lost
