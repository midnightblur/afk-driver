# CLAUDE.md

Guidance for any agent working in this plugin.

## What this repo is

The **`afk` workflow plugin** — a chain of skills built on [Matt Pocock's AFK workflow/skills](https://github.com/mattpocock/skills), adapted so that every external system — tracker, forge, notes store, build gate — is an adapter the consuming repository selects (`ADAPTERS.md`, `CONFIG.md`). **AFK = "away from keyboard"** (definition: `GLOSSARY.md`) — **human-heavy at the edges, autonomous in the middle**: design (grills → PRD → SDD → plan) and final acceptance (CR/Merge, smoke verdict review) are interactive; implementation runs hands-off via **`/afk-toolkit:autopilot`** (each stage can also run by hand). Chain: raw idea → grilled requirements → PRD → (optional) **UI mockup** (`/afk-toolkit:prototype`) → architecture → SDD → (optional) **grilled verification scenarios** (`/afk-toolkit:grill-verification` interviews → `/afk-toolkit:to-verification-plan` writes `VERIFICATION-PLAN.md`: UI journeys + API scenarios) → **local execution plan** (`plan/` dir of subtask contracts, not Jira issues) → execution (`/afk-toolkit:autopilot` hands-off, or `/afk-toolkit:execute` per subtask) → **feature smoke gate** (`/afk-toolkit:smoke-test` — full when a `VERIFICATION-PLAN.md` drove the plan, minimal otherwise; every plan has one).

Workflow skills live under `skills/afk/<name>/SKILL.md`; standalone utilities live under `skills/utils/<name>/SKILL.md`. Manifests, hooks, agents, harness adapters, the four capability adapter families (`ADAPTERS.md`) and the tracker MCP server share this tree. The *work* the chain drives lives in the consuming repository, which describes itself in `.afk/config.yaml` (`CONFIG.md`). Jira is written by exactly two skills: `/afk-toolkit:to-ticket` publishes the design-chain PRD's requirements-level ticket description into the parent Enhancement/Story/Bug and (spinoff mode) mints stub Enhancements for grill-deferred work, and `/afk-toolkit:bug`'s publisher subagent creates a Bug + one Dev-Pending transition + evidence comments on that ticket only (ADR-0001); SDD, subtask plan, and progress live on disk. GitLab (`glab`) is SCM.

No package build step. Edit the shared source, run the hook tests and gates, then refresh the enabled plugin per `PROVIDERS.md`.

## Plugin layout & install

Plugin: native manifests in `.claude-plugin/` and `.codex-plugin/`, shared `.mcp.json`, skills, hooks, agents, and provider stubs. Both manifests declare the same skill directories. Install and refresh through the active harness; commands live in `README.md` and `PROVIDERS.md`.

## How to write these skill files (treat prose like code)

These `SKILL.md` + sibling `.md` files are the program the agent runs — same engineering discipline. KISS, DRY, YAGNI, modularization, in English:

- **Write with the doctrine loaded.** Before creating or editing any `SKILL.md` or sibling, invoke `skills/utils/writing-for-agents` and apply it while writing — doctrine at write time, not after-the-fact audits.
- **Frontier model only.** Any session/agent editing this plugin or its harness runs the frontier model tier (`DELEGATION.md` "Model selection") — a plugin defect multiplies into every run the plugin drives.
- **Opt-in boundary.** No artifact a change ships may affect a dev who has not enabled the plugin. `PROVIDERS.md` "Distribution law" binds every change.
- **Generic, never feature-specific.** State the *mechanism*, not a story. No war-stories, no worked examples from a real ticket/feature, no naming a concrete feature to illustrate a step. Unavoidable example → make it obviously hypothetical. Enforced by `hooks/genericity-gate.sh` (Stop gate: ticket IDs + product-symbol references in added plugin prose; deliberate references go in `hooks/genericity-allow.txt` with a reason).
- **Downstream is blind to upstream.** A skill invoked later must not name the skill/stage calling it or assume who ran first — what it needs arrives at invocation. Upstream may name its downstream; the reverse is the failure. (A steward/registry file may state its own read/write contract without naming callers — not a pipeline reference. Nor is gap-routing: a skill detecting a gap it doesn't own may name the skill that owns fixing it as a bounce target — forbidden is naming/assuming who *called* it.)
- **DRY — one fact, one home.** State each fact (enumeration, format, recipe, rule) in exactly ONE file — its owning file — every other skill *points* by path, never restates. The pointing skill reads the pointed-at file anyway, so a copy is pure duplication that goes stale. E.g. `/afk-toolkit:grill-requirements` says "go through the staples in `STAPLES.md`"; it does **not** list them — the list lives in `STAPLES.md`, read regardless. Where Lockstep sanctions a synchronized copy (emitter/parser needs literal grammar/section shape), the copy is legal only at the emitting/parsing site, tagged with its owning file — every other mention is a pointer.
- **Lazy load / progressive disclosure.** Surface an instruction only where needed. Keep `SKILL.md` to trigger + spine; push detail (formats, long checklists, procedures) into sibling `.md` loaded on demand (existing `[X.md]` pattern). Don't front-load what only one branch needs.
- **Single-writer artifacts** — one steward writes a shared on-disk artifact, every other skill reads (see "Section ownership invariants"; don't restate the map here).
- **Less is more.** Cut every word carrying no fact the reader acts on. Sacrifice grammar for concision — drop articles, filler, connective prose; keep precision + completeness intact (a shorter file that loses a fact failed). No narration, motivation, "unlike X" cross-refs, or meta-commentary. State action + constraints, once.
- **Minimal-first.** Start with the least instruction that can do the job; add detail only on observed failure, never preemptively. An over-specified instruction is a defect even when correct.
- **Deterministic-first.** Mechanical work (validation, grep walks, table edits, format checks) goes in a script the skill invokes — never prose the agent re-derives per run. A trigger must be deliverable: an instruction that fires on time passing, on a child's silence, or on an external state change names the mechanism whose exit or event delivers it (script, background watchdog, hook, notification) — a trigger the idle agent cannot receive is a defect even when the instruction is correct.
- **Compact artifacts.** Every markdown artifact a skill *writes at runtime* follows `LANGUAGE.md` §3 (plugin root). Root docs are NOT auto-loaded at invocation, so each emitter/template carries an explicit *read-`LANGUAGE.md`-before-writing* instruction (never a restatement).

## Harness-agnostic by default

- Ship one committed plugin tree for every supported harness. Use each harness's native enable flag.
- Do not add generators, mirrors, or generated-and-committed files.
- Keep harness-specific tool names and environment variables out of skill prose.
- Use only Agent Skills frontmatter and documented harness extensions. Declare capability needs in `CAPABILITIES.md`.
- Give `CLAUDE_PROJECT_DIR` and `PLUGIN_ROOT` a fallback. Use only hook events in `CAPABILITIES.md`'s shared subset.
- Put provider behavior in `hooks/lib/providers/<name>.sh`. Update `PROVIDERS.md` in the same change.
- Add a harness through `providers/CONFORMANCE.md`'s checklist.

## Human followability (binding on every skill)

Speed is worthless if the human can't stay on top of it. Three plugin-root files govern this; skills point at them, never restate:

- **`LANGUAGE.md`** — the one home for how the plugin writes (which words, whose terms, how much), binding on every producing surface, current and future. Every `SKILL.md` and agent definition opens with a one-line pointer to it (enforced by `hooks/skill-registry-gate.sh` check D) — a new skill without that line fails the gate; every emitter/template carries a read-first pointer.
- **`REPORTING.md`** — reporting protocol: every terminal status line followed by one jargon-free `In plain terms:` sentence + a pointer to the full story; notifications never carry a bare status token; abbreviations expand at first use. Any skill emitting `OUTCOME:` / `AUTOPILOT:` / `REVIEW:` / `ADVERSARY:` lines follows it.
- **`GLOSSARY.md`** (plugin root) — one home for workflow-methodology vocabulary (L1–L9 legend, modes, states, verdicts, artifact names). Domain vocabulary stays in the target repo's glossaries. Point here for these terms.

Followability artifacts + stewards: **ticket index** (`INDEX.md`, read-this-first dashboard — created by `/afk-toolkit:to-prd`, each later synthesis skill upserts only its own row); **journal** (`plan/JOURNAL.md`, append-only event log — seeded by `/afk-toolkit:to-subtasks`, appended by `/afk-toolkit:execute`, `/afk-toolkit:autopilot`, `/afk-toolkit:smoke-test`, `/afk-toolkit:preflight`, `/afk-toolkit:understand`; append-only is the one sanctioned multi-writer pattern); **review rollup** (`plan/review/INDEX.md`, owned by `/afk-toolkit:review`); **trace matrix** (`plan/TRACE.md`, emitted once by the terminal sync-harness subtask); **grill log** (`GRILL-LOG.md`, one section per grill skill).

## Context protection (binding on every skill)

The orchestrating agent's context window is the run's scarcest resource. **`DELEGATION.md`** (plugin root) owns the doctrine: must-delegate triggers (bulk reads, repo-wide searches, suite/build runs, large diffs, external intake), spawn rules (parallel-in-one-message, background think-time overlap in interactive phases, named agent types, nesting cap), return contract (terse cited digest, bulk evidence to a file), and what must never be delegated (the human conversation, conversation synthesis, single-writer stamps). Skills point at it, never restate. A step matching a trigger delegates even where a skill's own prose predates the doctrine.

## Freshness (binding on every change)

No plugin-source artifact may go stale — an agent trusts what it reads. **`FRESHNESS.md`** (plugin root) owns the doctrine: **same-commit rule** (a change adding/removing/changing an external dependency updates the dependency register `skills/afk/setup/MANIFEST.md` in the same commit; a change adding/renaming/removing a skill or plugin artifact updates every surface its registry row names in the same commit) and **artifact registry** (plugin-source artifact → steward → update triggers). Drift catcher: **`/afk-toolkit:setup audit`** (`skills/afk/setup/AUDIT.md`) — run before shipping plugin changes. Skills point here, never restate. (Runtime artifacts — plan/, INDEX.md, journal — governed by "Section ownership invariants" below.)

## The skills

Per-skill mechanics, refusal conditions, and formats live in each skill's own `SKILL.md` + siblings — the catalog below routes, restates nothing. Utility skills (`skills/utils/`) are standalone, not AFK-chain, invoked with the same `/afk-toolkit:` prefix. *(agent)* = agent-invoked, hidden from the `/` menu (`user-invocable: false`).

**Mandatory chain**: `/afk-toolkit:to-prd` → `/afk-toolkit:to-ticket` → `/afk-toolkit:to-subtasks` → `/afk-toolkit:autopilot` (or `/afk-toolkit:execute` per subtask by hand) → `/afk-toolkit:smoke-test`. The design layer (`grill-requirements`, `prototype`, `grill-solution`, `to-sdd`, `to-design-brief`) and verification design (`grill-verification` → `to-verification-plan`) are optional pre-stages — recommended for new complex features, skipped for small bugs / refactors / tooling. `/afk-toolkit:to-subtasks` always seeds one terminal `NNNN-sync-harness` doc subtask (blocked by every other subtask, run last) that syncs the CLAUDE.md harness for the shipped feature and settles the staples registry by delegating to `/afk-toolkit:claude-md`.

**Staples registry.** A *staple* is a delivered capability that became a standing expectation (e.g. deep-linking, Excel import/export): once it exists, every future feature whose work matches its trigger must consider adopting it. Staples live in a per-service `{service}/STAPLES.md` registry (self-documenting format + the staples) — **stewarded solely by `/afk-toolkit:claude-md`** (its third steering-artifact, alongside CLAUDE.md and `.claude/rules`), read-only everywhere else. Two loops thread it through the chain: **consult** (design side) — `/afk-toolkit:grill-requirements` matches each `active` staple's trigger and grills in/out (+ raises new-staple candidates), `/afk-toolkit:to-prd` records the call as acceptance criteria + a requirement ADR and carries the candidate, `/afk-toolkit:grill-solution`/`/afk-toolkit:to-sdd` design the accepted ones, `/afk-toolkit:to-subtasks` turns them into Acceptance bullets + seams so `/afk-toolkit:execute` builds them, `/afk-toolkit:review` (spec-fidelity) checks they were honoured; **capture** (delivery side) — the `NNNN-sync-harness` subtask makes the authoritative call on candidates and advances Reference exemplars. Reshaping a `STAPLES.md` field touches only `/afk-toolkit:claude-md` (the writer); consulting skills point at the file, don't restate its shape.

## Lockstep: the subtask plan contract

The plan is the load-bearing interface between `/afk-toolkit:to-subtasks` (emitter) and `/afk-toolkit:execute` (parser + progress writer). Entirely on disk: `plan/PLAN.md` (index — solution map, seam register, progress tracker) + one `plan/NNNN-slug.md` contract per subtask, sibling to `PRD.md`/`SDD.md`. A subtask's **id** is its filename stem (`NNNN-slug`); no Jira keys in the plan. Adding/renaming/changing a section → update **both** `skills/afk/to-subtasks/SKILL.md` ("Subtask contract" emitter) and `skills/afk/execute/SKILL.md` (Step 1 parser) in the same commit — same repo so this lockstep is enforced by one commit. Likewise the outcome status set (now including `adversary_fail`): broadening it → update the status list in `/afk-toolkit:execute` Step 13 and any skill referencing a status by name. Autopilot's park handling is deliberately status-agnostic — its step 4 parks on anything that is not a recognised success — so a new status needs no edit there, and its absence from `skills/afk/autopilot/SKILL.md` is not drift. Smoke gate has two shapes — full (`## Feature smoke gate`) and minimal (`## Feature smoke gate (minimal)`) — same three-way lockstep: `to-verification-plan` emitter (full only), `to-subtasks` seeder (both, incl. minimal-gate template in its SMOKE-GATE.md), `smoke-test` reader (both). Independent review gate is its own lockstep set: `/afk-toolkit:execute` Step 10 and `/afk-toolkit:preflight` PF-3 both invoke `/afk-toolkit:review` (slice / `--feature`) inside the settle loop (`skills/afk/review/SETTLEMENT.md` — round structure, fix-or-dispute, dispute adjudication, ledger-only and stalemate termination, scope escalation, the park-report contract, referee information diet) and route findings by `class` — change `/afk-toolkit:review`'s verdict set, `class` enum, concern list, or the settle-loop protocol → update both gates' routing (and the PF-3 `Cycle`-cell cap copy in `skills/afk/to-subtasks/PLAN-TEMPLATE.md`) in the same commit. The `product-debt` class is its own lockstep set: the class + its homing rule are owned by `/afk-toolkit:review` ("Product-debt homes"), the `## Known debt` entry shape by `/afk-toolkit:claude-md`, the filter by `SETTLEMENT.md` step 2, and the enforcement by `/afk-toolkit:preflight` PF-4d (+ its `PLAN-TEMPLATE.md` row), and the reviewer-facing prohibition by `skills/afk/review/checklists/PRECEDENCE.md` (rule 6) — change any → all six in the same commit. The review **gate policy** (`lean`/`full`) is its own lockstep set: split + resolution owned by `/afk-toolkit:review` "Gate policy" ↔ emitters `skills/afk/to-subtasks/SUBTASK-CONTRACT.md` (`## Review`) + `PLAN-TEMPLATE.md` (`Review policy:` header) ↔ the deferral declarations in `/afk-toolkit:execute` Step 10 and `/afk-toolkit:preflight` PF-3 (rule mechanics: `skills/afk/review/SETTLEMENT.md` "Deferral rule") ↔ the deferrable-concern copy in `validate_plan.py` (h) — change any → all in the same commit. The adversarial gate is its own pair: change `/afk-toolkit:adversary`'s verdict set or finding classes → update `/afk-toolkit:execute` Step 10.5's gate logic in the same commit. A concern add/rename/removal also touches its `skills/afk/review/checklists/{concern}.md` and (design-level) the trigger table in review's SKILL.md; the caller-side outcome files (`plan/review/*.outcomes.json`) and `/afk-toolkit:retro`'s criterion-yield mining share the findings-JSON `criterion`/`id` shape — widen it → touch execute Step 10, preflight PF-3, and retro's mining table in the same commit. The human-locked set is a four-file lockstep: aspects + contract grades + signing protocol owned by `skills/afk/grill-solution/HUMAN-SIGNOFF.md`, recorded through the signoff-row grammar in `skills/afk/grill-requirements/GRILL-LOG-FORMAT.md`, carried into `skills/afk/to-sdd/SDD-TEMPLATE.md` (§0 register + each aspect's section) and enforced by `/afk-toolkit:to-sdd`'s sign-off gate — change the set or a grade → all four in the same commit. The lesson ledger is its own lockstep set: event grammar / class enum / status set owned by `skills/afk/lessons/LEDGER-FORMAT.md`, sole emitting site `hooks/lesson-append.sh`, sole parsing site `hooks/lesson-digest.sh` — change any → all three in the same commit; the escape-analysis miss-class set (`skills/afk/fix/ESCAPE-ANALYSIS.md`) ↔ the miss-class mapping table in LEDGER-FORMAT.md is a second pair; and the detection-point capture sentences (execute Steps 4/10/10.5, autopilot Finish, fix Phase 3.5 + `WORKFLOW-FEEDBACK.md`, claude-md HARVEST, glossary GRILL, harvest Steps 1-5, retro mining/family 8, preflight PF-4c) all point at `skills/afk/lessons/CAPTURE.md` — reshaping that protocol touches every pointer in the same commit.

Contract base sections: `## Goal / Complexity / Scope / Acceptance / Verification / Context excerpts / Parent PRD / Blocked by`, plus optional `## Review` (slice review-gate policy/opt-ins — semantics `skills/afk/review/SKILL.md` "Gate policy") (`Context excerpts` = slicing-time verbatim PRD/SDD/ADR quotes the executor works from, full-doc reads only on a gap; absent in older plans → executor falls back to reading the parent docs). `## Complexity` (`mechanical | standard | complex`, enum owned by `skills/afk/to-subtasks/SUBTASK-CONTRACT.md`) sizes the executing subagent — autopilot routes model/reasoning-effort on it; absent reads as `standard`. `## Verification` is a **tiered table** (static → unit → integration → api → e2e/browser); a row names a tier KEY from the repository's `verification.tiers`, never a command; implementor must turn every declared tier green. Cited mode adds six: `## Design refs / Seams / Produces / Parent SDD / Consumes / Conflict procedure`.

`/afk-toolkit:execute` owns the PLAN.md progress tracker's `Status` column (`pending` → `designing` → `developing` → `verifying` → `reviewing` → `done`, or `blocked(<reason>)`) — one cell per run. `reviewing` is the independent review gate (Step 10) — a settle loop (`skills/afk/review/SETTLEMENT.md`) that re-reviews after every remediation until a round finds nothing actionable; a 10-round stalemate sets `blocked(review_fail: …)`. Everything else in the plan is the human's.

## Cited-mode contract

The contract is enforced at three checkpoints — drift can't ship without surfacing somewhere:

1. **Slicing time (`/afk-toolkit:to-subtasks` Validation).** Checks (a)–(d):
   - **Graph validation (a)** — every `## Consumes` line resolves to a `## Produces` bullet on a subtask earlier in rank order. Forward refs / orphan consumers / multi-producer collisions all bounce.
   - **Anchor quality (b)** — every `## Produces` `{grep-anchor}` checked against the forbidden-generic-token list + length + uniqueness rules owned by `skills/afk/to-subtasks/VALIDATION.md` (b). Ambiguous anchors that would fail-open at runtime are rejected at declaration time.
   - **Acceptance citations (c)** + **seam coverage (d)** — every cited Acceptance bullet ends with a resolving citation tag; every SDD §9b seam appears in the seam register with a named implementer listing it `implement:` and carrying its seam-test as a `## Verification` row.
2. **Consumer preflight (`/afk-toolkit:execute` Step 2).** Reads `## Design refs` + `## Parent SDD` for binding SDD/ADR context. Then for each `## Consumes` line `{PRODUCER-ID} {file}#{grep-anchor}`, reads `{file}` and greps `{grep-anchor}`. A miss exits `contract_mismatch` carrying the producer id (no retry; record on both consumer and producer subtask files + set both tracker rows `blocked`). A binding-decision break follows the conflict procedure (`skills/afk/execute/CITED-MODE.md`): a two-way-door correction is recorded in `plan/DECISIONS.md` (protocol: root `DECISIONS.md`) and implemented; a one-way door or tie exits `design_conflict` (no retry; routes to `/afk-toolkit:grill-solution`).
3. **Producer self-preflight (`/afk-toolkit:execute` Step 9).** Just before declaring `success`, greps each of its own `## Produces` anchors on the branch. A miss exits `produces_drift` (no retry; route the human to fix impl OR re-emit the slice).

`## Produces` is mandatory on every cited subtask, even leaves with no consumer — it doubles as the reviewer's cheat-sheet, the producer-self-preflight grep target, the `static`-tier grep target, AND the next subtask's consumer-preflight grep target.

**Materialized seams (opt-in upgrade of the same contract).** With `materialize_seams=true`, `/afk-toolkit:to-subtasks` pre-creates each new-Java seam's stub + `@Disabled` contract-shape test on the branch at slicing time and marks the affected `Produces`/`Consumes` bullets `[materialized]` — those contracts are then **compiler**-checked at every checkpoint (consumer preflight adds `test-compile`; producer self-preflight requires the contract test enabled), grep-anchors remaining the fallback for existing-file and non-Java seams. Marker grammar is part of the same emitter/parser lockstep (`SUBTASK-CONTRACT.md` ↔ `execute/CITED-MODE.md`); the human commits materialized files with the plan — `/afk-toolkit:to-subtasks` never commits.

## Section ownership invariants (don't violate)

- **Parent Enhancement description**: PRD content authored by `/afk-toolkit:to-prd` (on disk), published into the parent — distilled to a requirements-level ticket description (`TICKET.md`) in native Jira formatting (ADF), inside an AFK-managed sentinel block — by `/afk-toolkit:to-ticket`, which preserves all content outside that block. The SDD is **not** published to the ticket — `/afk-toolkit:to-sdd` writes it (and the Design Brief via `/afk-toolkit:to-design-brief`) to disk only. The **Meeting Summaries** region — a `Meeting Summaries` heading plus one collapsible `expand` per meeting (keyed by expand title) — is also owned by `/afk-toolkit:to-ticket` (its standalone *meeting mode*, `scripts/publish_meeting.py`), disjoint from the PRD sentinel block; attaches to any ticket, not just a design-chain parent. Other prose belongs to the human. (Subtask progress is **no longer** spliced into the parent — lives in the local `plan/PLAN.md` tracker.)
- **MR description**: the `<!-- afk:subtasks:start --> ... <!-- afk:subtasks:end -->` checklist block is auto-maintained by `/afk-toolkit:execute`; everything outside preserved verbatim.
- **The local plan (`plan/`)**: `/afk-toolkit:execute` owns only the PLAN.md progress-tracker `Status` cell of the subtask it runs (+ `Last updated` date). **`/afk-toolkit:smoke-test`** owns a disjoint slice of the same PLAN.md — the `## Feature smoke gate` table's `Status` cells, its `Last run` line, its append-only `Run history` lines, and the header `Feature:` line — nothing else. **`plan/JOURNAL.md`** is append-only multi-writer (`/afk-toolkit:execute`, `/afk-toolkit:autopilot`, `/afk-toolkit:smoke-test`, `/afk-toolkit:preflight`, `/afk-toolkit:understand` append; nobody edits/deletes a prior line; format owned by `skills/afk/to-subtasks/JOURNAL-FORMAT.md`). **`plan/DECISIONS.md`** (the decision ledger) is append-only under the same rule — classification + grammar owned by root `DECISIONS.md`; writers append via that protocol, readers: every executor before working a slice, the orchestrator's end-of-run report. **`plan/review/`** (reports + `INDEX.md` + `PATTERN-DEBT.md`) owned by `/afk-toolkit:review`, with two disjoint co-writers under their own naming: `/afk-toolkit:adversary`'s report files, and the review gate's callers' `*.outcomes.json` remediation records. **`plan/TRACE.md`** written once by the terminal sync-harness subtask. **Lifespan**: `plan/` is a run artifact — lives from slicing to merge; after the MR merges, `/afk-toolkit:gc` (human-approved) deletes it whole, git history the archive — the one sanctioned post-ship deletion.
- **The lesson ledger** (main-checkout `.claude/lessons/LEDGER.jsonl`): append-only multi-writer, written **only** through `hooks/lesson-append.sh` (grammar + resolution: `skills/afk/lessons/LEDGER-FORMAT.md`); nobody edits or deletes a prior line; status transitions beyond capture belong to `/afk-toolkit:lessons`.
- **The ticket index (`INDEX.md`)**: created by `/afk-toolkit:to-prd` (owns the summary paragraph, seeds every row); each synthesis skill upserts **only its own row(s)** of the artifact table (format + row-ownership map: `skills/afk/to-prd/INDEX-FORMAT.md`). Rows for artifacts a feature never produces stay `—`.
- **A service's `## Known debt` section** (any `CLAUDE.md` in the target repo): sole writer `/afk-toolkit:claude-md`, which owns the entry shape and the propose-approve-write protocol; `/afk-toolkit:review` routes `product-debt` findings to it and `/afk-toolkit:preflight` PF-4d enforces that an accepted one has an entry. Why it is not under `plan/`: `/afk-toolkit:review` "Product-debt homes".
- **The grill log (`GRILL-LOG.md`)**: one `##` section per grill skill, each grill writes only its own section (format: `skills/afk/grill-requirements/GRILL-LOG-FORMAT.md`).
- Plan contract sections must round-trip losslessly. Adding a section → update both the `/afk-toolkit:to-subtasks` emitter and the `/afk-toolkit:execute` parser together (see Lockstep above); a section read by `/afk-toolkit:smoke-test` (the gate) must update in lockstep with that skill too. The `## Feature smoke gate` is seeded from `VERIFICATION-PLAN.md` (written by `/afk-toolkit:to-verification-plan` from a `/afk-toolkit:grill-verification` interview, covering both UI journeys and API scenarios) and the build-subtasks' authoring recipes are whatever the consuming repository names as its own (referenced, never copied) — change a gate field's shape → touch all three (`to-verification-plan` emitter, `to-subtasks` seeder, `smoke-test` reader) in the same commit.

## Skill ↔ human ownership split (CR/Merge)

`/afk-toolkit:execute` drives the progress-tracker status (`designing` → `developing` → `verifying` → `reviewing` → `done`), the TDD loop, the verification tiers, the independent review gate (`/afk-toolkit:review`, Step 10), commits, push, and the MR checklist — then **stops**. It does NOT merge the MR. The human reviews the Draft MR and merges (and writes any gate fields) out of band. Auto-merging is outside the skill's lane — preserve this boundary when editing `/afk-toolkit:execute`.

## Tracker boundary

Exactly two Jira writers (ADR-0001): **`/afk-toolkit:to-ticket`** — parent-ticket description publish + re-publish delta comments + spinoff stub Enhancements (mechanics: `skills/afk/to-ticket/SKILL.md`) — and **`/afk-toolkit:bug`**'s publisher subagent — create Bug + one Dev-Pending transition + evidence comments, that ticket only (`skills/afk/bug/SKILL.md`). Everything else stops at disk or GitLab: `/afk-toolkit:to-prd`, `/afk-toolkit:to-sdd`, `/afk-toolkit:grill-verification`, `/afk-toolkit:to-verification-plan`, `/afk-toolkit:to-subtasks`, `/afk-toolkit:to-design-brief`, `/afk-toolkit:to-demo-plan`, `/afk-toolkit:smoke-test` **local-only**; `/afk-toolkit:prototype` **local-first**, sole network egress an **opt-in** `claude.ai/design` push (share mirror, never Jira/GitLab/merge); `/afk-toolkit:execute` touches **GitLab** (push + Draft MR) + the local plan, **not Jira** — subtasks are local artifacts, progress lives in `plan/PLAN.md`.

## Conventions to keep

- **Branch names** must match the repository's own `git.branch-pattern`, and a new branch is named from its `git.branch-template`; both are load-bearing for `/afk-toolkit:execute`'s push. Enforcement (**agent-only**): `hooks/branch-name-gate.sh` (a git `reference-transaction` hook) refuses **creation** of a new local branch that does not match the configured pattern, and prints the expanded template. A repository declaring no pattern gets no gate. Human-driven creation in a terminal or IDE, and checkouts of existing or remote-tracking branches, stay untouched. Auto-installed on `SessionStart`; `/afk-toolkit:setup` (register H5) and a manual installer are fallbacks. Bypass one agent command with `AFK_SKIP_BRANCH_CHECK=1`; disable per clone with `git config afk.branchNameGate false`.
- **Two ADR tiers, separate subfolders.** Requirement-level ADRs (what/why): `.../{TICKET-ID}/adr/requirements/NNNN-*.md`, owned by `/afk-toolkit:to-prd`. Design-level ADRs (how): `.../{TICKET-ID}/adr/design/NNNN-*.md`, owned by `/afk-toolkit:to-sdd`. Numbering local to each subfolder; tiers never share numbering. Retired repo-wide `docs/adr/` is gone — all ADRs ticket-local.
- **Plugin paths pin to the installed plugin root.** Any runtime instruction reading/executing a plugin file (skill, hook, script) writes the path as `${AFK_PLUGIN_ROOT}/…` (term: `GLOSSARY.md` "Main checkout") — never repository-relative, because the plugin is installed, not checked out beside the work. Spawn prompts and templates fill their placeholders (`{WORKFLOW_SKILLS_DIR}`, `{WORKFLOW_HOOKS_DIR}`, `{main checkout}`) from the same rule; scripts resolving siblings via `$BASH_SOURCE` are exempt (self-relative is stable).
