# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## What this repo is

The **`afk` Claude Code plugin** — a chain of skills built on [Matt Pocock's AFK workflow/skills](https://github.com/mattpocock/skills), adapted to Nakisa's Jira + GitLab + Maven monorepo. **AFK = "away from keyboard":** heavy effort up front on requirements + design, then agents implement autonomously. Deliberate split: **human-heavy at the edges, autonomous in the middle.** Design (grills → PRD → SDD → plan) and final acceptance (CR/Merge, smoke verdict review) are interactive; implementation runs hands-off via **`/afk:autopilot`** — sequential driver executing every subtask in a fresh subagent (driven-mode `/afk:execute`), self-provisions the live app for `api`/`e2e`/adversarial verification, parks failures (+ dependents) while independent work continues, ends at feature smoke gate. Each stage can also run interactively by hand — autopilot is the default for the middle, not the only way. Chain: raw idea → grilled requirements → PRD → (optional) **UI mockup** (`/afk:prototype`) → architecture → SDD → (optional) **grilled verification scenarios** (`/afk:grill-verification` interviews → `/afk:to-verification-plan` writes `VERIFICATION-PLAN.md`: UI journeys + API scenarios) → **local execution plan** (`plan/` dir of subtask contracts, not Jira issues) → execution (`/afk:autopilot` hands-off, or `/afk:execute` per subtask) → **feature smoke gate** (`/afk:smoke-test` — full when a `VERIFICATION-PLAN.md` drove the plan, minimal otherwise; every plan has one).

Repo contains only skills — workflow skills under `skills/afk/<name>/SKILL.md`, general-purpose utility skills (not AFK-chain) under `skills/utils/<name>/SKILL.md` — plus plugin manifests. The *work* the chain drives is Java/Maven in a sibling core-services checkout. Jira (`mcp__jira__*`) is tracker **only for the parent Enhancement/Bug**, written by exactly two skills: `/afk:to-ticket` publishes the design-chain PRD there, and `/afk:bug`'s publisher subagent creates a Bug + one Dev-Pending transition + evidence comments on that ticket only (ADR-0001); SDD, subtask plan, and progress live on disk. GitLab (`glab`) is SCM.

No Python package, no test suite, no build step — edit a `SKILL.md`, run `/reload-plugins`; that's the dev loop.

## Plugin layout & install

Plugin: `.claude-plugin/plugin.json` (manifest) + `.claude-plugin/marketplace.json` (local marketplace) + `skills/afk/<name>/SKILL.md` (AFK-chain) + `skills/utils/<name>/SKILL.md` (standalone utilities) — both dirs declared in manifest's `skills` array (replaces default `skills/` scan since marketplace `source` resolves to repo root). Install once via `/plugin marketplace add <repo>` + `/plugin install afk@nak-marketplace`, persist via `enabledPlugins` in `~/.claude/settings.json`. After editing any `SKILL.md`, run `/reload-plugins`. Full install snippet: `README.md`.

## How to write these skill files (treat prose like code)

These `SKILL.md` + sibling `.md` files are the program the agent runs — same engineering discipline. KISS, DRY, YAGNI, modularization, in English:

- **Generic, never feature-specific.** State the *mechanism*, not a story. No war-stories, no worked examples from a real ticket/feature, no naming a concrete feature to illustrate a step. Unavoidable example → make it obviously hypothetical. Enforced by `hooks/genericity-gate.sh` (Stop gate: ticket IDs + product-symbol references in added plugin prose; deliberate references go in `hooks/genericity-allow.txt` with a reason).
- **Downstream is blind to upstream.** A skill invoked later must not name the skill/stage calling it or assume who ran first — what it needs arrives at invocation. Upstream may name its downstream; the reverse is the failure. (A steward/registry file may state its own read/write contract without naming callers — not a pipeline reference. Nor is gap-routing: a skill detecting a gap it doesn't own may name the skill that owns fixing it as a bounce target — forbidden is naming/assuming who *called* it.)
- **DRY — one fact, one home.** State each fact (enumeration, format, recipe, rule) in exactly ONE file — its owning file — every other skill *points* by path, never restates. The pointing skill reads the pointed-at file anyway, so a copy is pure duplication that goes stale. E.g. `/afk:grill-requirements` says "go through the staples in `STAPLES.md`"; it does **not** list them — the list lives in `STAPLES.md`, read regardless. Where Lockstep sanctions a synchronized copy (emitter/parser needs literal grammar/section shape), the copy is legal only at the emitting/parsing site, tagged with its owning file — every other mention is a pointer.
- **Lazy load / progressive disclosure.** Surface an instruction only where needed. Keep `SKILL.md` to trigger + spine; push detail (formats, long checklists, procedures) into sibling `.md` loaded on demand (existing `[X.md]` pattern). Don't front-load what only one branch needs.
- **Single-writer artifacts** — one steward writes a shared on-disk artifact, every other skill reads (see "Section ownership invariants"; don't restate the map here).
- **Less is more.** Cut every word carrying no fact the reader acts on. Sacrifice grammar for concision — drop articles, filler, connective prose; keep precision + completeness intact (a shorter file that loses a fact failed). No narration, motivation, "unlike X" cross-refs, or meta-commentary. State action + constraints, once.

## Human followability (binding on every skill)

Speed is worthless if the human can't stay on top of it. Two plugin-root files govern this; skills point at them, never restate:

- **`REPORTING.md`** — reporting protocol: every terminal status line followed by one jargon-free `In plain terms:` sentence + a pointer to the full story; notifications never carry a bare status token; abbreviations expand at first use. Any skill emitting `OUTCOME:` / `AUTOPILOT:` / `REVIEW:` / `ADVERSARY:` lines follows it.
- **`GLOSSARY.md`** (plugin root) — one home for workflow-methodology vocabulary (L1–L9 legend, modes, states, verdicts, artifact names). Domain vocabulary stays in the target repo's glossaries. Point here for these terms.

Followability artifacts + stewards: **ticket index** (`INDEX.md`, read-this-first dashboard — created by `/afk:to-prd`, each later synthesis skill upserts only its own row); **journal** (`plan/JOURNAL.md`, append-only event log — seeded by `/afk:to-subtasks`, appended by `/afk:execute`, `/afk:autopilot`, `/afk:smoke-test`, `/afk:preflight`, `/afk:understand`; append-only is the one sanctioned multi-writer pattern); **review rollup** (`plan/review/INDEX.md`, owned by `/afk:review`); **trace matrix** (`plan/TRACE.md`, emitted once by the terminal sync-harness subtask); **grill log** (`GRILL-LOG.md`, one section per grill skill).

## Context protection (binding on every skill)

The orchestrating agent's context window is the run's scarcest resource. **`DELEGATION.md`** (plugin root) owns the doctrine: must-delegate triggers (bulk reads, repo-wide searches, suite/build runs, large diffs, external intake), spawn rules (parallel-in-one-message, named agent types, nesting cap), return contract (terse cited digest, bulk evidence to a file), and what must never be delegated (the human conversation, conversation synthesis, single-writer stamps). Skills point at it, never restate. A step matching a trigger delegates even where a skill's own prose predates the doctrine.

## Freshness (binding on every change)

No plugin-source artifact may go stale — an agent trusts what it reads. **`FRESHNESS.md`** (plugin root) owns the doctrine: **same-commit rule** (a change adding/removing/changing an external dependency updates the dependency register `skills/afk/setup/MANIFEST.md` in the same commit; a change adding/renaming/removing a skill or plugin artifact updates every surface its registry row names in the same commit) and **artifact registry** (plugin-source artifact → steward → update triggers). Drift catcher: **`/afk:setup audit`** (`skills/afk/setup/AUDIT.md`) — run before shipping plugin changes. Skills point here, never restate. (Runtime artifacts — plan/, INDEX.md, journal — governed by "Section ownership invariants" below.)

## The skills

- **Mandatory chain**: `/afk:to-prd` → `/afk:to-ticket` → `/afk:to-subtasks` → `/afk:autopilot` (or `/afk:execute` per subtask by hand) → `/afk:smoke-test`. `/afk:to-ticket` publishes the local PRD to the parent Enhancement (the only design-chain skill writing to the tracker). `/afk:to-subtasks` emits a **local plan** (`plan/PLAN.md` index + `plan/NNNN-slug.md` per subtask) — no Jira. `/afk:autopilot` runs subtasks hands-off (or run `/afk:execute` yourself, once per subtask); either way the executor advances each subtask's row in the local progress tracker. `/afk:to-subtasks` always seeds one terminal `NNNN-sync-harness` doc subtask (blocked by every other subtask, run last by `/afk:execute`) that syncs the CLAUDE.md harness for the shipped feature **and settles the staples registry** by delegating to `/afk:claude-md`.

**Staples registry.** A *staple* is a delivered capability that became a standing expectation (e.g. deep-linking, Excel import/export): once it exists, every future feature whose work matches its trigger must consider adopting it. Staples live in a per-service `{service}/STAPLES.md` registry (self-documenting format + the staples) — **stewarded solely by `/afk:claude-md`** (its third steering-artifact, alongside CLAUDE.md and `.claude/rules`), read-only everywhere else. Two loops thread it through the chain: **consult** (design side) — `/afk:grill-requirements` matches each `active` staple's trigger and grills in/out (+ raises new-staple candidates), `/afk:to-prd` records the call as acceptance criteria + a requirement ADR and carries the candidate, `/afk:grill-solution`/`/afk:to-sdd` design the accepted ones, `/afk:to-subtasks` turns them into Acceptance bullets + seams so `/afk:execute` builds them, `/afk:review` (spec-fidelity) checks they were honoured; **capture** (delivery side) — the `NNNN-sync-harness` subtask makes the authoritative call on candidates and advances Reference exemplars. Reshaping a `STAPLES.md` field touches only `/afk:claude-md` (the writer); consulting skills point at the file, don't restate its shape.
- **Optional design layer**: `/afk:grill-requirements` (raw-idea grilling; maintains `GLOSSARY.md` only — no decision records) → `/afk:to-prd` (PRD + requirement ADRs under `.../adr/requirements/`; **local only — no tracker**) → (optional) `/afk:prototype` (**interactive UI-crafting loop**, not a grill nor one-shot producer: reads PRD User Stories, anchors to the **real frontend's** components + tokens, writes self-contained HTML the user opens/refreshes, reshapes live; self-gates `no_ui` for backend/API/refactor features; durable-lite output — won direction is `PROTOTYPE.md` + chosen HTML sibling to the PRD, traceable to User Stories so `/afk:grill-verification`'s UI journeys trace to it, losing scaffolding discarded; **local-first**, with a **frictionless opt-in** push to a persistent team-shareable `claude.ai/design` project that is a share mirror only — in-repo `PROTOTYPE.md` stays canonical) → `/afk:grill-solution` (top-down L1→L9 interview — L9 = implementation-seam walk + parallel compatibility audit vs existing code) → `/afk:to-sdd` (writes `SDD.md` + per-decision design ADRs under `.../adr/design/` sibling to the PRD; **local only — no tracker**) → `/afk:to-design-brief` (optional digest: synthesizes PRD + SDD + ADRs into a 1-2 page `DESIGN-BRIEF.md` for stakeholder review + pre-SDD reading; **repo-only — no tracker**, shared out of band). Recommended for new complex features; skip small bugs / refactors / tooling.
- **Optional verification design**: `/afk:grill-verification` (interview) → `/afk:to-verification-plan` (synthesis). `/afk:grill-verification` interviews to design the feature's verification scenarios across **two modalities** — writes only its `GRILL-LOG.md` checkpoint section (a grill, like `/afk:grill-requirements` and `/afk:grill-solution`); `/afk:to-verification-plan` synthesizes settled scenarios into `VERIFICATION-PLAN.md` sibling to the PRD: **UI journeys** (real browser flows deciding "this feature works", traced to PRD User Stories) and **API scenarios** (direct-REST checks proving the backend contract for API/MCP callers bypassing the UI, traced to SDD §3 endpoints). Walking them concretely routinely surfaces PRD/SDD gaps. **UI journeys** can be designed after `/afk:to-prd`; **API scenarios need the SDD's §3 endpoint contracts**, so a pre-SDD run designs UI journeys only and defers the API section — re-run both skills after `/afk:to-sdd` to add it (`/afk:to-verification-plan` **appends**, preserving the UI section). **Local-only — no tracker.** Its plan makes `/afk:to-subtasks` emit the smoke gate + a build subtask per modality. Test-authoring recipes are **not in this repo** — they live canonically in payable at `11700-payable/verification/ui-e2e/AUTHORING.md` and `11700-payable/verification/api/AUTHORING.md` (versioned with the verification code so they can't drift); every AFK skill only **points** by path, never embeds a copy.
- **Feature gate (always present)**: `/afk:smoke-test` — the **feature-level** completion gate (distinct from `/afk:execute`'s per-subtask `api` / `e2e/browser` tiers). **Only executes** already-built checks — authors nothing. Every plan carries a gate: the **full** gate when a `VERIFICATION-PLAN.md` (from `/afk:grill-verification`) drove `/afk:to-subtasks` to emit a `## Feature smoke gate` in `PLAN.md` plus a terminal build subtask **per modality** — `NNNN-smoke-e2e` (UI journeys → `Scenario`s in the `11700-payable/verification/ui-e2e` Cucumber+Playwright catalog, per `…/ui-e2e/AUTHORING.md`) and `NNNN-smoke-api` (API scenarios → `node:test` `*.test.mjs` in `11700-payable/verification/api` using `../core`, per `…/api/AUTHORING.md`) — reviewed as code; env-limited scenarios like `@sap` / GL-post are tagged and excluded from the gate's green verdict. After **every** subtask is `done`, `/afk:smoke-test` runs both modalities (`npm run smoke` + `node --test`) against a **running app** and, only on green across both, stamps `Feature: complete` in `PLAN.md`. Same suites reused by CI / scheduled / manual runs. Merges nothing, writes no Jira. Features **without** a `VERIFICATION-PLAN.md` get the **minimal** gate (`## Feature smoke gate (minimal)`: compile / app-start / regression / existing-suites — template in `skills/afk/to-subtasks/SMOKE-GATE.md`); its green stamp says `(minimal gate)` so it's never mistaken for scenario-verified.
- **Ship gate**: `/afk:preflight` — chained by `/afk:autopilot` once the feature smoke gate is green (or run by hand to resume a parked feature). Table-driven, resumable PF-1..7 ladder in `PLAN.md`'s `## Preflight` section (its sole writer): merges `origin/master` behind an ancestry guard (never rebase, never force-push), re-runs validations, a fresh integrated review, and a final `/afk:verify-seams final` check within a shared 2-cycle fix cap, commits the mission-control end-state snapshot, updates the MR's own evidence marker block (sibling to `/afk:execute`'s checklist block — each writer replaces only its own), and background-babysits CI (bundled `ci-wait.sh`, exit 0/1/2/3) to flip the Draft MR to Ready. Refuses outright — writing nothing — without a green smoke gate. Never merges the MR; CI-only test reds and secret hits always park, never auto-fixed.
- **Hands-off driver**: `/afk:autopilot` — walks the whole plan in rank order (Blocked-by respected), one fresh subagent per subtask running `/afk:execute` in **driven mode** (prompt template `skills/afk/autopilot/SUBAGENT-PROMPT.md`), self-provisions the live app per slice (`hooks/app-start-gate.sh`, shipped with this plugin — invoked from repo root as `bash tools/payable/ai-agents/plugins/workflow/hooks/app-start-gate.sh`), parks failed subtasks + their dependents while independent subtasks continue (push notification on every park, per `REPORTING.md`), appends run-level events + a per-subtask heartbeat to `plan/JOURNAL.md`, then runs `/afk:smoke-test`. Sequential v1 — no parallel subtasks. Writes no PLAN.md cell (single-writer stays with the executor); commit+push per subtask on the feature branch authorized only inside its runs.
- **Adversarial execution gate**: `/afk:adversary` — `/afk:execute` Step 10.5. A fresh session probes the **running app** with scenarios derived from the contract + specs under a hard information diet (never the diff / implementor tests). Verdict `clean`/`findings`(classed)/`tainted`/`env_unreachable`; blocking findings route by `class` like review findings and share Step 10's 2-cycle remediation cap; terminal → `adversary_fail`. Lockstep: change `/afk:adversary`'s verdict set or finding classes → update execute Step 10.5's gate logic in the same commit.
- **Bug pipeline (interactive-only, outside the feature chain)**: `/afk:bug` — mid-task bug capture + autonomous fix, five subcommands `capture`/`dispatch`/`status`/`retest`/`purge` (frozen set, `skills/afk/bug/SKILL.md`). `capture` writes the evidence bundle + ledger entry to disk before any external call, then files a Jira Bug (the plugin's second, narrowly-scoped Jira writer — see "Tracker boundary"). `dispatch` spawns an autonomous fixer in its own worktree (`scripts/create-worktree`) under a one-live-fixer-across-all-bugs invariant, delivering a Draft MR the human merges — the fixer never merges. `status` is read-only situational awareness; `retest` re-runs the reproduction once the fix lands, read-only. `purge` is the only cleanup path. Refuses `capture`/`dispatch` when invoked hands-off (driven/autopilot) — a human must be in the loop to file a ticket or spawn a fixer. State machine, bundle grammar, and config keys are one-home in its own `LEDGER-FORMAT.md`/`BUNDLE-FORMAT.md`/`CONFIG.md` siblings.
- **Tooling**: `tdd` skill (red-green-refactor doctrine, invoked from `/afk:execute` Step 5; agent-invoked, hidden from `/` menu via `user-invocable: false`). `/afk:review` (**independent post-verification review gate** — fresh parallel subagents, one per concern, each briefed verbatim with its book-derived checklist from `skills/afk/review/checklists/`; implementation/conformance concerns always run, design-level concerns (`design-quality`/`domain-alignment`/`resilience`/`api-contract`) activate by diff-shape trigger, and design-level findings pass an adversarial skeptic wave before they can gate; **read-only** — returns a ranked findings report + a `clean`/`advisory`/`blocking` verdict (`pattern-debt` findings never gate — they feed `plan/review/PATTERN-DEBT.md`, the evidence trail for evolving documented patterns), never edits/commits; invoked from `/afk:execute` Step 10, from `/afk:preflight` PF-3 as `--feature` over the integrated diff, also standalone as `/afk:review {NNNN-slug}`). `/afk:fix` (disciplined bug-fix orchestration — wraps `/afk:diagnose` + proportional `api`/`e2e` coverage + a Phase-2.5 **escape analysis** of the existing test that should have caught the bug + feature-session artifact reconciliation + a Phase-3.5 **workflow-feedback handoff** (`/afk:handoff`) for AFK-delivered features so the chain stops repeating the miss; routed from `/afk:execute` Step 8 on a stuck verification tier **and from the Step 10 review gate on a `correctness`/`spec` blocking finding**, also standalone for ad-hoc bugs). `/afk:setup` (workflow doctor — probes every entry of the dependency register `skills/afk/setup/MANIFEST.md`, auto-fixes what it can, guides the human through secrets; idempotent, so first install and post-pull repair are one flow; `base` branch adds the register's base-tier fields — the version-pinned monorepo toolchain; `audit` branch = the Freshness drift catcher above). `/afk:claude-md` (steward of the three steering artifacts — CLAUDE.md harness + role sidecars, `.claude/rules`, per-service `STAPLES.md` (see "Staples registry" above); propose → approve → write, never writes unasked; delegated to by the terminal `NNNN-sync-harness` subtask, also standalone). `/afk:retro` (cross-feature retrospective — mines delivered plans' journals, review rollups, adversary verdicts, park reasons, and harness gate-latency metrics into recurring signals + ≤5 evidence-cited plugin-edit proposals in a dated `RETRO-*.md`; read-only, human applies; systemic counterpart of `/afk:fix`'s escape analysis). `/afk:design-system` (per-service setup, outside the per-feature chain — builds/refreshes the team-shareable `claude.ai/design` catalog mirroring the service's live frontend that `/afk:prototype` anchors to; re-run on token/component drift). `/afk:mission-control` (launches the per-feature read-only dashboard — watch mode for a live run, `--once` for a retroactive render of a finished feature; only recovery from a crashed watcher is relaunching the skill — no daemonization). `/afk:understand` (**post-ship feature understanding artifact** — one self-contained interactive HTML explainer per feature at `{spec-dir}/understanding/index.html`, synthesized from the feature's actual diff + journal + review records: dual-depth background, intuition, seam-ordered diff walkthrough, notable plan-deviations, opt-in quiz; one pipeline, two modes — **auto** from `/afk:preflight`'s advisory ladder row, defaults + one docs-only commit, never blocks a ship; **standalone** `/afk:understand {plan-dir}`, prompts + writes-no-commit; fully offline, surfaced by `INDEX.md` + the mission-control understanding panel; section model/predicates/quiz rules/meta-header grammar one-homed in `skills/afk/understand/UNDERSTANDING-FORMAT.md`, chrome in the checked-in `shell-template.html`).

- **Utility skills** (`skills/utils/`, standalone — not AFK-chain, invoked with the same `/afk:` prefix): `/afk:diagnose` (disciplined diagnosis loop — reproduce → minimise → hypothesise → instrument → fix → regression-test; wrapped by `/afk:fix`, also standalone). `/afk:handoff` (compact the current conversation into a handoff document another agent picks up). `/afk:glossary` (domain-vocabulary steward — `GLOSSARY-MAP.md` + per-service domain `GLOSSARY.md`; vocabulary only, distinct from the plugin-root workflow `GLOSSARY.md`). `/afk:todo` (per-project todo list that survives sessions). `/afk:caveman` (ultra-compressed reply mode). `/afk:to-code-walkthrough` (nine-layer narrative walkthrough of a GitLab MR or code area — explanatory, no verdicts). `/afk:writing-great-skills` (reference for authoring/auditing skills). Agent-invoked only (`user-invocable: false`, hidden from `/` menu): `verify-seams` (orphan hunt — the wiring gate's judgment tier), `draw-charts` (render-safe diagram authoring), `interactive-walkthrough` (HTML walkthrough widget templates).

`/afk:to-subtasks` slices in **cited mode** when an SDD is present (each subtask references binding SDD sections + ADRs, lists the §9b seams it implements/uses, carries a Conflict procedure block), **uncited mode** otherwise (PRD-only; human-gated per ticket). Mode set by what's upstream: PRD + SDD (from `/afk:grill-solution`) → cited; PRD only (from `/afk:grill-requirements`) → uncited.

## Lockstep: the subtask plan contract

The plan is the load-bearing interface between `/afk:to-subtasks` (emitter) and `/afk:execute` (parser + progress writer). Entirely on disk: `plan/PLAN.md` (index — solution map, seam register, progress tracker) + one `plan/NNNN-slug.md` contract per subtask, sibling to `PRD.md`/`SDD.md`. A subtask's **id** is its filename stem (`NNNN-slug`); no Jira keys in the plan. Adding/renaming/changing a section → update **both** `skills/afk/to-subtasks/SKILL.md` ("Subtask contract" emitter) and `skills/afk/execute/SKILL.md` (Step 1 parser) in the same commit — same repo so this lockstep is enforced by one commit. Likewise the outcome status set (now including `adversary_fail`): broadening it → update the status list in `/afk:execute` Step 13, the autopilot park handling, and any skill referencing it. Smoke gate has two shapes — full (`## Feature smoke gate`) and minimal (`## Feature smoke gate (minimal)`) — same three-way lockstep: `to-verification-plan` emitter (full only), `to-subtasks` seeder (both, incl. minimal-gate template in its SMOKE-GATE.md), `smoke-test` reader (both). Independent review gate is its own lockstep set: `/afk:execute` Step 10 and `/afk:preflight` PF-3 both invoke `/afk:review` (slice / `--feature`), gate on its `clean`/`advisory`/`blocking` verdict, and route `blocking` findings by `class` — change `/afk:review`'s verdict set, `class` enum, or concern list → update both gates' routing in the same commit. A concern add/rename/removal also touches its `skills/afk/review/checklists/{concern}.md` and (design-level) the trigger table in review's SKILL.md; the caller-side outcome files (`plan/review/*.outcomes.json`) and `/afk:retro`'s criterion-yield mining share the findings-JSON `criterion`/`id` shape — widen it → touch execute Step 10, preflight PF-3, and retro's mining table in the same commit.

Contract base sections: `## Goal / Complexity / Scope / Acceptance / Verification / Parent PRD / Blocked by`. `## Complexity` (`mechanical | standard | complex`, enum owned by `skills/afk/to-subtasks/SUBTASK-CONTRACT.md`) sizes the executing subagent — autopilot routes model/reasoning-effort on it; absent reads as `standard`. `## Verification` is a **tiered table** (static → unit → integration → api → e2e/browser, where `api` is a direct-REST endpoint check via `11700-payable/verification/api` + `../core`); implementor must turn every declared tier green. Cited mode adds six: `## Design refs / Seams / Produces / Parent SDD / Consumes / Conflict procedure`.

`/afk:execute` owns the PLAN.md progress tracker's `Status` column (`pending` → `designing` → `developing` → `verifying` → `reviewing` → `done`, or `blocked(<reason>)`) — one cell per run. `reviewing` is the independent review gate (Step 10); a gate staying `blocking` after two remediation cycles sets `blocked(review_fail: …)`. Everything else in the plan is the human's.

## Cited-mode contract

The contract is enforced at three checkpoints — drift can't ship without surfacing somewhere:

1. **Slicing time (`/afk:to-subtasks` Validation).** Checks (a)–(d):
   - **Graph validation (a)** — every `## Consumes` line resolves to a `## Produces` bullet on a subtask earlier in rank order. Forward refs / orphan consumers / multi-producer collisions all bounce.
   - **Anchor quality (b)** — every `## Produces` `{grep-anchor}` checked against (i) forbidden-generic-token list (`class`, `interface`, `void`, `function`, `def`, `method`, `struct`, `enum`, `type`, `record`); (ii) length ≥12 chars; (iii) trial `ctx_search` against `{file}` at HEAD must return ≤1 match. Ambiguous anchors that would fail-open at runtime are rejected at declaration time.
   - **Acceptance citations (c)** + **seam coverage (d)** — every cited Acceptance bullet ends with a resolving citation tag; every SDD §9b seam appears in the seam register with a named implementer listing it `implement:` and carrying its seam-test as a `## Verification` row.
2. **Consumer preflight (`/afk:execute` Step 2).** Reads `## Design refs` + `## Parent SDD` for binding SDD/ADR context. Then for each `## Consumes` line `{PRODUCER-ID} {file}#{grep-anchor}`, reads `{file}` and greps `{grep-anchor}`. A miss exits `contract_mismatch` carrying the producer id (no retry; record on both consumer and producer subtask files + set both tracker rows `blocked`). A binding-decision break exits `design_conflict` (no retry; routes to `/afk:grill-solution`).
3. **Producer self-preflight (`/afk:execute` Step 9).** Just before declaring `success`, greps each of its own `## Produces` anchors on the branch. A miss exits `produces_drift` (no retry; route the human to fix impl OR re-emit the slice). Without this, signature drift surfaces only at the next consumer's preflight — on the wrong subtask.

`## Produces` is mandatory on every cited subtask, even leaves with no consumer — it doubles as the reviewer's cheat-sheet, the producer-self-preflight grep target, the `static`-tier grep target, AND the next subtask's consumer-preflight grep target.

**Materialized seams (opt-in upgrade of the same contract).** With `materialize_seams=true`, `/afk:to-subtasks` pre-creates each new-Java seam's stub + `@Disabled` contract-shape test on the branch at slicing time and marks the affected `Produces`/`Consumes` bullets `[materialized]` — those contracts are then **compiler**-checked at every checkpoint (consumer preflight adds `test-compile`; producer self-preflight requires the contract test enabled), grep-anchors remaining the fallback for existing-file and non-Java seams. Marker grammar is part of the same emitter/parser lockstep (`SUBTASK-CONTRACT.md` ↔ `execute/CITED-MODE.md`); the human commits materialized files with the plan — `/afk:to-subtasks` never commits.

## Section ownership invariants (don't violate)

- **Parent Enhancement description**: PRD content authored by `/afk:to-prd` (on disk), published into the parent — full inlined body in native Jira formatting (ADF), inside an AFK-managed sentinel block — by `/afk:to-ticket`, which preserves all content outside that block. The SDD is **not** published to the ticket — `/afk:to-sdd` writes it (and the Design Brief via `/afk:to-design-brief`) to disk only. The **Meeting Summaries** region — a `Meeting Summaries` heading plus one collapsible `expand` per meeting (keyed by expand title) — is also owned by `/afk:to-ticket` (its standalone *meeting mode*, `scripts/publish_meeting.py`), disjoint from the PRD sentinel block; attaches to any ticket, not just a design-chain parent. Other prose belongs to the human. (Subtask progress is **no longer** spliced into the parent — lives in the local `plan/PLAN.md` tracker.)
- **MR description**: the `<!-- afk:subtasks:start --> ... <!-- afk:subtasks:end -->` checklist block is auto-maintained by `/afk:execute`; everything outside preserved verbatim.
- **The local plan (`plan/`)**: `/afk:execute` owns only the PLAN.md progress-tracker `Status` cell of the subtask it runs (+ `Last updated` date). **`/afk:smoke-test`** owns a disjoint slice of the same PLAN.md — the `## Feature smoke gate` table's `Status` cells, its `Last run` line, its append-only `Run history` lines, and the header `Feature:` line — nothing else. **`plan/JOURNAL.md`** is append-only multi-writer (`/afk:execute`, `/afk:autopilot`, `/afk:smoke-test`, `/afk:preflight`, `/afk:understand` append; nobody edits/deletes a prior line; format owned by `skills/afk/to-subtasks/JOURNAL-FORMAT.md`). **`plan/review/`** (reports + `INDEX.md` + `PATTERN-DEBT.md`) owned by `/afk:review`, with two disjoint co-writers under their own naming: `/afk:adversary`'s report files, and the review gate's callers' `*.outcomes.json` remediation records. **`plan/TRACE.md`** written once by the terminal sync-harness subtask.
- **The ticket index (`INDEX.md`)**: created by `/afk:to-prd` (owns the summary paragraph, seeds every row); each synthesis skill upserts **only its own row(s)** of the artifact table (format + row-ownership map: `skills/afk/to-prd/INDEX-FORMAT.md`). Rows for artifacts a feature never produces stay `—`.
- **The grill log (`GRILL-LOG.md`)**: one `##` section per grill skill, each grill writes only its own section (format: `skills/afk/grill-requirements/GRILL-LOG-FORMAT.md`).
- Plan contract sections must round-trip losslessly. Adding a section → update both the `/afk:to-subtasks` emitter and the `/afk:execute` parser together (see Lockstep above); a section read by `/afk:smoke-test` (the gate) must update in lockstep with that skill too. The `## Feature smoke gate` is seeded from `VERIFICATION-PLAN.md` (written by `/afk:to-verification-plan` from a `/afk:grill-verification` interview, covering both UI journeys and API scenarios) and the build-subtasks' authoring recipes are the verification repo's `11700-payable/verification/{ui-e2e,api}/AUTHORING.md` (referenced, never copied) — change a gate field's shape → touch all three (`to-verification-plan` emitter, `to-subtasks` seeder, `smoke-test` reader) in the same commit.

## Skill ↔ human ownership split (CR/Merge)

`/afk:execute` drives the progress-tracker status (`designing` → `developing` → `verifying` → `reviewing` → `done`), the TDD loop, the verification tiers, the independent review gate (`/afk:review`, Step 10), commits, push, and the MR checklist — then **stops**. It does NOT merge the MR. The human reviews the Draft MR and merges (and writes any gate fields) out of band. Auto-merging is outside the skill's lane — preserve this boundary when editing `/afk:execute`.

## Tracker boundary

`/afk:to-prd` produces **local artifacts only** (PRD.md + requirement ADRs on disk); creates/updates no Jira/GitLab issue. Publishing the PRD to the tracker is **`/afk:to-ticket`**'s job: publishes **full PRD content** into an **existing** parent ticket's description as native Jira formatting (ADF — Jira Cloud), any `mermaid` blocks rendered to PNGs **locally**, attached, embedded inline as media nodes (verified media-UUID method; no diagram source leaves the network). **Idempotent** — PRD lives in an AFK-managed sentinel block, so re-running updates in place and replaces prior `afk-fig*` attachments rather than duplicating; content **outside** the managed block (product-owner prose) preserved verbatim unless the existing description is barebone. Intricate formatting/diagram/merge work codified in `skills/afk/to-ticket/scripts/publish_prd.py` for deterministic behavior (reads Jira creds from env or `~/.claude.json`, talks to REST API directly, since attachment upload has no MCP tool). Deliberately **does not** create the parent (refuses without `parent_key`), sets **no label**, creates **no GitLab branch** (`/afk:execute` self-creates its branch), publishes **PRD content only** — not SDD/Design Brief. **`/afk:to-ticket`** (PRD body) and **`/afk:bug`** (its publisher subagent — create Bug + one Dev-Pending transition + evidence comments, that ticket only, ADR-0001) are the plugin's only two Jira writers; everything else stops at disk or GitLab. `/afk:to-prd`, `/afk:to-sdd`, `/afk:grill-verification`, `/afk:to-verification-plan`, `/afk:to-subtasks`, `/afk:to-design-brief` are **local-only**; `/afk:prototype` is **local-first and tracker-free** — canonical output (`PROTOTYPE.md` + chosen HTML) on disk, its **only** network egress an **opt-in** `claude.ai/design` push (share mirror, never Jira/GitLab/merge); `/afk:execute` touches **GitLab** (push + Draft MR) + local plan, **not Jira** — subtasks are local artifacts, progress lives in `plan/PLAN.md`. `/afk:grill-verification` writes only its `GRILL-LOG.md` checkpoint section (interviews otherwise); `/afk:to-verification-plan` writes only `VERIFICATION-PLAN.md` (+ gap notes) on disk. `/afk:smoke-test` is **local-only too**: runs the verification suites (UI + API) against a target app, edits only its slice of `plan/PLAN.md` (the `## Feature smoke gate` Status cells + `Feature:` line) — no Jira, no GitLab push, no merge.

## Conventions to keep

- **Branch names** must match GitLab regex `^[a-z0-9][a-z0-9/\-\.]*$` — the `kapteyn/development/{username}/{enh_id_lower}` pattern is load-bearing for `/afk:execute`'s push. Enforcement (**agent-only**): `hooks/branch-name-gate.sh` (a git `reference-transaction` hook) refuses **creation** of a new local branch that doesn't match `kapteyn/development/<username>/<slug>` — but only when `CLAUDECODE` is set (i.e. the branch is being created by an agent). Human-driven creation in your own terminal/IDE, and checkouts of existing/remote-tracking branches, are never blocked. Auto-installed on `SessionStart` (`hooks/install-git-hooks.sh --quiet`, idempotent + self-scoping) so enabling the plugin is the only opt-in; `/afk:setup` (register H5) and a manual installer run are fallbacks. Bypass one agent command with `AFK_SKIP_BRANCH_CHECK=1`; disable per clone with `git config afk.branchNameGate false`.
- **Two ADR tiers, separate subfolders.** Requirement-level ADRs (what/why): `.../{TICKET-ID}/adr/requirements/NNNN-*.md`, owned by `/afk:to-prd`. Design-level ADRs (how): `.../{TICKET-ID}/adr/design/NNNN-*.md`, owned by `/afk:to-sdd`. Numbering local to each subfolder; tiers never share numbering. Retired repo-wide `docs/adr/` is gone — all ADRs ticket-local.
